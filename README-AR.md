# MYGRAM — تحديث 2.4

هذه الحزمة مبنية على ملفات المرحلة 2.3.1، مع إصلاح تعارض واجهة النشر مع قاعدة البيانات: أصبح حقل النص اختيارياً في HTML، بينما يتحقق `home.js` من وجود نص أو مرفق قبل النشر. كما تتغير شارة المنشور عند وجود مرفق.

## الملفات
ارفع **محتويات هذه الحزمة** إلى المجلد الرئيسي لمستودع GitHub `MYGRAM-DB/mygram-app`، واستبدل الملفات المتطابقة. لا ترفع ملف ZIP نفسه ولا تحذف ملفات قديمة غير موجودة في الحزمة.

## قاعدة البيانات
في هذه الجلسة تم تنفيذ وفحص ما يلي في Supabase:
- إضافة `media_url` و`media_type` إلى `public.posts`.
- إنشاء bucket باسم `mygram-media` بحد 50MB وأنواع ملفات محددة.
- إنشاء سياسات عرض الملفات ورفعها وتحديثها وحذفها ضمن مجلد المستخدم.
- تعديل `posts_content_check` للسماح بمنشور فارغ النص عندما يحتوي على `media_url`.

**لا تعِد تشغيل `phase2.3-storage.sql` بالكامل**؛ فهو يعيد إنشاء القيد والسياسات، وقد يغيّر إعدادات موجودة. الملف مرفق كمرجع فقط، وليس مطلوباً تشغيله مجدداً.

## فحوصات بعد الرفع
1. افتح `home.html` وسجّل الدخول.
2. تأكد من ظهور المنشور القديم `MYGRAM MY FIRST APP`.
3. جرّب نشر نص فقط.
4. جرّب اختيار صورة، ثم إزالة المرفق بواسطة ×.
5. جرّب نشر صورة مع نص، ثم صورة بلا نص.
6. افتح الملف الشخصي وجرّب اختيار صورة وحفظها.
7. إذا ظهر خطأ، صوّر الرسالة كاملة وأرسلها؛ لا تشغّل SQL إضافياً عشوائياً.

## ملاحظات أمان
- `config.js` يستخدم مفتاح Supabase publishable مخصصاً للواجهة؛ لا تضع مفتاح `service_role` أو أي مفتاح سري في ملفات الموقع.
- مخزن `mygram-media` عام لتمكين عرض الصور بروابط عامة؛ لا تستخدمه للملفات الخاصة.
- اجتياز فحص JavaScript لا يثبت عمل خدمات Supabase أو صلاحيات RLS على الموقع المنشور؛ يلزم اختبار فعلي بعد الرفع.
