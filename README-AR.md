# MYGRAM V3 — واجهة جديدة

## الملفات
- `index.html`: الصفحة الرئيسية والواجهة الاجتماعية.
- `styles.css`: تصميم متجاوب للهاتف والكمبيوتر مستوحى من المرجع المرسل.
- `app.js`: تفاعلات الواجهة وتسجيل الدخول/إنشاء الحساب، تحميل المنشورات، رفع مرفقات المنشورات، التفاعلات والتعليقات.
- `config.js`: عنوان Supabase والمفتاح العام.
- `services.html`, `profile.html`, `people.html`: صفحات مساندة.
- `.nojekyll`: يمنع معالجة Jekyll غير اللازمة في GitHub Pages.

## طريقة الرفع
1. نزّل ZIP واحتفظ بنسخة من ملفات المستودع الحالية.
2. ارفع محتويات المجلد إلى جذر مستودع GitHub، وليس ملف ZIP نفسه.
3. تأكد أن `index.html` في جذر المستودع؛ لا تغيّر إعداد GitHub Pages.
4. افتح رابط Pages وانتظر نشر آخر Commit.

## Supabase
إعدادات الاتصال العامة موجودة في `config.js`. لا تضع `service_role` أو أي secret في الواجهة.
الكود يفترض أن جدول `profiles` يملك `id` مرتبطًا بالمستخدم، وأن `posts` يتيح `user_id` و`content`. يحاول تحميل رابط الوسائط من `media_url` أو `image_url`. قد تحتاج مواءمة أسماء الأعمدة وفق مخطط مشروعك الفعلي. رفع الوسائط يتطلب bucket باسم `post-media` وسياسة Storage مناسبة، وقراءة/إنشاء المنشورات تتطلب سياسات RLS مناسبة.

## حدود الوظائف
الواجهة الجديدة تتضمن تسجيل الدخول وإنشاء الحساب، عرض المنشورات، إنشاء المنشورات مع مرفقات، التفاعلات والتعليقات على مستوى الربط الأولي. صفحات القصص والريلز والرسائل واكتشاف الأعضاء توضح أماكن الخدمات لكنها ليست تنفيذًا كاملًا للخدمات الحية. لا توجد طريقة صادقة لضمان اكتمال الربط قبل مطابقة المخطط والسياسات واختبارها في مشروع Supabase الفعلي.
