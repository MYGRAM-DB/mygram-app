# تجهيز مزوّدي MYGRAM للاختبار التجريبي

هذه قائمة تشغيل عملية للإعداد اليدوي. **لا تضع أي سرّ في GitHub أو ملفات JavaScript أو في محادثات عامة.** كل مفاتيح الخادم تضاف في لوحة المزود أو في Supabase Edge Function Secrets.

## ما هو موجود حالياً وما ينتظر الربط

| الخدمة | تجهيز الكود | الإعداد المطلوب قبل الاختبار الحقيقي |
|---|---|---|
| GitHub Pages | الواجهة الحالية منشورة من main | نشر هذا الفرع بعد نجاح CI والدمج فقط |
| Supabase Auth + قاعدة البيانات | جلسات، بريد/كلمة مرور، واجهة Google والهاتف | تدقيق URL settings ومزوّدي Google/SMS والبريد |
| Google OAuth | زر التدفق موجود ويُرسل المستخدم إلى Supabase OAuth | إنشاء OAuth client وإدخال Client ID/Secret في Supabase |
| SMS/OTP | واجهة رقم الهاتف والرمز موجودة | تفعيل Phone provider وربط مزوّد SMS واختبار تسليم حقيقي |
| البريد | إنشاء حساب/تأكيد/استعادة/رابط دخول موجودة في الواجهة | SMTP مرسل موثوق، نطاق موثّق، واختبار رسائل فعلية |
| مكالمات فردية صوت/فيديو | WebRTC + إشارات call_signals موجودة في MYGRAM Chat | TURN credentials، صلاحيات الميكروفون/الكاميرا، اختبار شبكات مختلفة |
| اجتماعات الفيديو | صفحة Meetings + meetings-token موجودة | LIVEKIT_URL, LIVEKIT_API_KEY, LIVEKIT_API_SECRET |
| محاضر AI متعددة اللغات | meeting-ai-minutes موجودة | مزوّد متوافق مع Chat Completions، مفتاح، نموذج ورصيد |
| الإشعارات الصوتية | نغمات محلية وأزرار كتم | لا تحتاج مفتاح مزوّد؛ تحتاج إجراء مستخدم أولاً للسماح بتشغيل الصوت بالمتصفح |

الوضع الحالي لا يعني أن Google أو SMS أو SMTP أو TURN أو LiveKit موصول بالفعل. لا نعتبرها ناجحة إلا بعد استخدام بيانات اعتمادك واختبار وصول فعلي.

## 1. Google OAuth

1. افتح Google Cloud Console واختر مشروعاً مناسباً أو أنشئ مشروعاً للاختبار.
2. أكمل إعداد OAuth consent screen، وحدد جمهور الاختبار وأضف حسابات المختبرين إذا كان التطبيق في وضع Testing.
3. أنشئ OAuth Client ID من نوع **Web application**.
4. في **Authorized redirect URIs** أضف رابط callback الخاص بـ Supabase:

   https://rocztskcyakvekokftfx.supabase.co/auth/v1/callback

   هذا هو رابط عودة Google إلى Supabase، وليس صفحة GitHub Pages.
5. من Supabase Dashboard → Authentication → Sign In / Providers → Google، فعّل المزود وأدخل Client ID وClient Secret واحفظ.
6. من Authentication → URL Configuration، اضبط Site URL إلى:

   https://mygram-db.github.io/mygram-app/

   وأضف Redirect URL للاختبار:

   https://mygram-db.github.io/mygram-app/**

   ويمكن إضافة رابط التطوير المحلي فقط عند الحاجة، مثل http://localhost:4173/**.
7. سجّل الخروج من حساب اختبار، واضغط زر Google، واختر الحساب، وتأكد من العودة إلى MYGRAM وإنشاء جلسة دائمة. اختبر أيضاً رفض العودة إذا كان الرابط غير مسموح.

**لا** تضع Google Client Secret في config.js أو auth.js. إن تعذر استخدام Google، يجب أن تظل كلمة المرور والبريد فعّالين.

## 2. الهاتف ورسائل OTP القصيرة

1. أنشئ حساباً في مزود SMS يدعم البلدان التي ستختبر منها. تختلف التغطية والتكلفة واشتراطات تسجيل Sender ID حسب البلد وشبكة الهاتف.
2. من Supabase Dashboard → Authentication → Sign In / Providers، فعّل Phone authentication، واختر مزود SMS المتاح وأدخل بياناته في حقول Supabase المخصصة.
3. اضبط طول OTP ومدة صلاحيته وحدود الإرسال/إعادة الإرسال. ابدأ بحدود ضيقة لتقليل إساءة الاستخدام وفاتورة الرسائل.
4. اختبر بالتسلسل: رقم بصيغة E.164، وصول الرسالة، رمز صحيح، رمز خاطئ، رمز منتهي، إعادة إرسال، ورقم غير مدعوم.
5. لا تجعل نجاح إرسال الطلب في الواجهة دليلاً على وصول SMS؛ يجب التحقق من سجل التسليم لدى المزود ومن الهاتف المستلم.

الواجهة تبني رقم E.164 من رمز الدولة، لكن أرقام الهواتف والقواعد الوطنية يجب التحقق منها بأرقام حقيقية. لا تبدأ باختبار جماعي على 205 دولة، بل اختر 2–3 دول أولاً.

## 3. البريد الإلكتروني، تأكيد الحساب والاستعادة

1. استخدم مرسل SMTP transactional، ووثّق نطاق الإرسال بـ SPF/DKIM (وDMARC عندما يكون مناسباً).
2. خيار مبدئي للتجربة: Resend، خطته المجانية الحالية تعرض 3,000 رسالة شهرياً بحد 100 يومياً، بشرط إعداد النطاق والمرسل. راجع السعر والحدود قبل الاعتماد.
3. من Supabase Dashboard → Project Settings / Authentication SMTP Settings أو إعداد SMTP ضمن Auth، أدخل Host وPort وUsername وPassword وSender name/address طبقاً لقيم مزود البريد.
4. راجع Email Templates وروابط العودة؛ يجب أن تعود رسائل التأكيد والاستعادة إلى نطاق MYGRAM وروابط مسموح بها.
5. اختبر تأكيد التسجيل، إعادة الإرسال، تسجيل الدخول برابط، استعادة كلمة المرور وتعيين كلمة جديدة من جلسة استعادة صحيحة. راجع مجلد spam وسجلات التسليم.

لا تستخدم كلمة مرور SMTP أو API key داخل الصفحة. إذا كان حساب Supabase على الخطة المجانية فلا تفترض أن بريد Auth المدمج مناسب للإطلاق الفعلي؛ اختبر SMTP مخصصاً.

## 4. المكالمات الصوتية والفيديو الفردية

مكالمات MYGRAM Chat الحالية مبنية على WebRTC وإشارات قاعدة البيانات؛ **لا تحتاج اتصالاً هاتفياً عادياً إلى رقم PSTN**. جودة الاتصال عبر بعض شبكات الهاتف/الشركات تحتاج TURN لتعمل عندما لا يكفي STUN.

### Cloudflare TURN

1. من Cloudflare Realtime / Calls أنشئ TURN key للبيئة التجريبية.
2. أضف القيمتين في Supabase → Edge Functions → Secrets:
   - CLOUDFLARE_TURN_KEY_ID
   - CLOUDFLARE_TURN_KEY
3. دالة turn-credentials تصدر بيانات ICE مؤقتة للمستخدم المسجل، بعد فحص عضويته في محادثة MYGRAM Chat.
4. اختبر بين جهازين على شبكتين مختلفتين، ثم شبكة هاتف خلوي، وافحص حالات: منح/رفض الميكروفون، رفض الكاميرا، الرد، الرفض، إنهاء المكالمة وانقطاع الشبكة.

إذا لم يكن TURN معدّاً، قد تعمل المكالمات في بعض الشبكات وتفشل في أخرى. لا نعتبر STUN وحده دعماً كاملاً لكل الشبكات.

## 5. اجتماعات LiveKit حتى 31 مشاركاً

أضف الأسرار التالية في Supabase Edge Function Secrets؛ تستخدمها meetings-token، ولا تضفها إلى المتصفح:

- LIVEKIT_URL
- LIVEKIT_API_KEY
- LIVEKIT_API_SECRET

ثم اختبر اجتماعاً فعلياً بين عدة حسابات، أولاً بصوت فقط ثم فيديو، وجرّب كتم الميكروفون، إغلاق الكاميرا، الخروج وإعادة الانضمام، نقل الرئاسة، وإنهاء الاجتماع. سقف 31 يعني 31 مشاركاً إجمالاً بما فيهم المضيف، وليس 31 بالإضافة إليه.

## 6. محاضر الاجتماع والذكاء الاصطناعي

تتوقع دالة meeting-ai-minutes مزوداً يقبل صيغة Chat Completions وإخراج JSON. أضف الأسرار من Supabase Edge Function Secrets:

- MYGRAM_MEETING_AI_API_URL (لخادم متوافق، endpoint الخاص بـ Chat Completions)
- MYGRAM_MEETING_AI_API_KEY
- MYGRAM_MEETING_AI_MODEL

تستطيع الدالة استخدام مفاتيح MYGRAM_TRANSLATION_API_URL, MYGRAM_TRANSLATION_API_KEY, MYGRAM_TRANSLATION_MODEL البديلة عند إعدادها. يلزم رصيد لدى المزود، ولا يوجد مزود مدفوع مجاني مضمون.

**قيود النسخة الحالية:** التقاط الكلام يعتمد على SpeechRecognition في متصفح المشارك وميكروفونه المحلي، وليس تسجيلاً خادمياً لكل المشاركين مع تمييز المتحدثين. المحضر يظهر داخل حساب كل مشارك ويُصدّر إلى PDF عبر نافذة الطباعة؛ التوزيع التلقائي بالبريد وتخزين ملفات PDF الجاهزة لم يُنفذا بعد. لا تجمع النص إلا بموافقة صريحة من كل الحضور النشطين.

## 7. حدود الإنفاق المقترحة

- ابدأ بحسابات اختبار معلومة، وبلدان SMS قليلة، واجتماع فيديو تجريبي واحد أو اثنين.
- ضع حد إنفاق/تنبيهات لدى مزوّد الرسائل والـAI وخدمات الفيديو، وحدود إعادة إرسال OTP.
- لا تفعّل تسجيل فيديو أو رفع ملفات ضخمة في المرحلة الأولى.
- ابدأ بخطة مجانية لخدمات الفيديو ضمن الحصص المتاحة؛ انتقل إلى المدفوع فقط إذا أثبت الاختبار حاجة فعلية.
- سجّل تكلفة كل اختبار: عدد رسائل SMS، دقائق اتصال المشاركين، GB نقل الفيديو، دقائق تفريغ الصوت، وعدد ملخصات AI.

## 8. قائمة قبول قبل اعتبار النسخة التجريبية جاهزة

- [ ] OAuth Google يعمل من البداية للنهاية والعودة إلى الموقع صحيحة.
- [ ] رسائل تأكيد/استعادة البريد وصلت فعلياً.
- [ ] OTP وصل إلى أرقام حقيقية في الدول المستهدفة، وتم اختبار حد الإرسال.
- [ ] مكالمة صوتية وفيديو بين جهازين على شبكتين مختلفتين، مع TURN، نجحت.
- [ ] اجتماع بثلاثة حسابات نجح، وجرّب نقل الرئاسة وإنهاء الاجتماع.
- [ ] تم اختبار موافقة النص وسحبها، وصحة محضر عربي وإنجليزي ولغة أخرى قبل التوسيع.
- [ ] CI ينجح على آخر commit، ثم ينجح GitHub Pages deployment من main.
- [ ] لا توجد أسرار في GitHub ولا أخطاء Console أو طلبات فاشلة مجهولة السبب.
