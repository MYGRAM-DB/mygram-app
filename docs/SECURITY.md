# الأمن والصلاحيات

## 1. قواعد لا تقبل الاستثناء

- RLS مفعّل على كل جدول في schema مكشوفة.
- الصلاحية تتحدد عبر GRANT **وسياسة RLS معاً**.
- لا تُستخدم بيانات `user_metadata` القابلة لتعديل المستخدم كمرجع صلاحيات.
- لا يظهر Service Role Key أو أي سر خادم في JavaScript أو ملفات عامة أو سجلات.
- لا تُعطّل RLS لحل خطأ وصول.
- كل UPDATE يحتاج سياسة قراءة متوافقة وقيود `USING` و`WITH CHECK` حسب الحالة.
- الروابط الخاصة للوسائط تكون قصيرة العمر ومقصورة على المشاركين.

## 2. خط الأساس المقاس

- جميع الجداول العامة الـ51 في Production عليها RLS.
- لا يُسمح لـ`anon` بقراءة جداول المحتوى والرسائل الخاصة وفق جرد GRANT الحالي؛ قوائم الدول واللغات وكتالوج الترجمة لها قراءة عامة مقصودة.
- لا توجد سياسة عامة بديلة تلغي الحاجة إلى فحص سياسات كل جدول.
- جميع جداول Staging الستة عليها RLS.
- `mygram-media` حاوية عامة، لذلك لا يُرفع إليها محتوى خاص.
- `mygram-private-messages` حاوية خاصة وسياساتها تربط القراءة بعضوية محادثة أو طرف رسالة.

## 3. مراجعة SECURITY DEFINER

مستشار Supabase أظهر ثلاثة RPCs عامة متاحة للمستخدم المسجل:
- `public.join_meeting(text,text)`
- `public.transfer_meeting_chair(uuid,uuid,text)`
- `public.update_meeting_status(uuid,text)`

مراجعة أجسام الوظائف أظهرت فحوصاً لـ`auth.uid()`، وقيوداً على صلاحيات المضيف/الرئيس، وانتقالات حالة الاجتماع. هذا فحص أولي وليس اعتماداً أمنياً. يجب إضافة اختبارات سلبية وإيجابية للتحقق من:
- مستخدم غير عضو أو بلا جلسة.
- مستخدم ليس مضيفاً ولا رئيساً.
- مشارك مغادر أو غير نشط.
- اجتماع منتهٍ أو ملغى.
- محاولات سباق أو إعادة طلب متكرر.

لا تُحوّلها إلى SECURITY INVOKER أو تسحب صلاحية EXECUTE قبل التحقق من تأثير ذلك على التدفق المشروع. تبقى ملاحظة المستشار مفتوحة إلى أن تنجح الاختبارات ويعاد تشغيل الفحص.

## 4. الدوال الخاصة

بعض دوال `private` المساعدة من نوع SECURITY DEFINER أظهرت EXECUTE لـanon في جرد Postgres. كونها في schema خاصة يقلل التعرض عبر Data API، لكنه لا يلغي ضرورة مراجعة صلاحيات schema ووجود أي مسار اتصال مباشر إليها. تُراجع دوال Trigger وHelpers وتُسحب الصلاحيات غير اللازمة في Migration مستقلة بعد اختبارها.

## 5. ملفات المستخدمين

- `profiles` يحتوي حقول العرض العامة.
- `profile_private_details` وحقول التفضيلات هي نطاق أكثر حساسية.
- لا تُعرض معلومات الاتصال أو بيانات الميلاد أو تفاصيل الحساب لمستخدم آخر بلا سياسة واضحة.
- يلزم معالجة تعارضات أسماء المستخدمين قبل تثبيت ضمان تفرد غير حساس لحالة الأحرف.

## 6. ملاحظات أمنية حالية

- Supabase Advisor يرصد حماية كلمات المرور المسرّبة غير مفعّلة. الحساب الحالي على Free بحسب سياق المشروع، والميزة تحتاج خطة مدفوعة في التسعير الحالي؛ لا تُفعّل عبر التفاف غير موثوق. يوثّق ذلك كخطر، وتُستخدم سياسات كلمات المرور وحدود المحاولات وCAPTCHA حيث تتوفر كطبقات إضافية.
- يوجد تحذير 5 مفاتيح أجنبية بلا فهارس؛ يعالج بعد مراجعة الاستعلامات وMigration غير مدمرة.
- لا تُحذف الفهارس التي تظهر غير مستخدمة في Advisor اعتماداً على تقرير منفرد أو قاعدة بيانات قليلة النشاط.

## 7. الاختبارات الإلزامية

- RLS SELECT/INSERT/UPDATE/DELETE لكل دور مناسب.
- الوصول العرضي بين مستخدمين ومنتجين.
- Storage upload/read/delete لمالك الملف وغير المالك.
- فحص صلاحيات Edge Functions وJWT.
- Rate limiting، والتحقق من المدخلات، وحدود الحجم والنوع.
- تدقيق الأسرار وسجلات الأخطاء.
