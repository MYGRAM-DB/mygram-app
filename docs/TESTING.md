# استراتيجية الاختبار والجودة

## 1. المبدأ

وجود ملف أو زر أو نجاح GitHub Actions لا يثبت اكتمال الوظيفة. كل ميزة تُصنف حسب أدلة الاختبار.

## 2. مستويات الاختبار

1. Unit Tests: تحقق من منطق الدوال والمكونات.
2. Integration Tests: تكامل الخدمات والقاعدة والتخزين.
3. API Tests: المدخلات والمخرجات والمصادقة وحدود الاستخدام.
4. Database Tests: القيود والمعاملات والـTriggers.
5. RLS Tests: السماح والمنع لكل عملية ولكل مستخدم.
6. Security Tests: الوصول غير المصرح وتسريب الأسرار وBOLA/IDOR.
7. Playwright E2E: رحلة المستخدم الفعلية في المتصفح.
8. Mobile/Responsive: عرض واستخدام الهاتف.
9. Performance: حجم الصفحات والتحميل والاستعلامات.
10. Regression: الوظائف السابقة التي تأثرت بالتغيير.
11. Financial Integrity: توازن القيود والتزامن وعدم تكرار الصرف.

## 3. الاختبارات المضافة في هيكل التأسيس

- `npm test` يشغّل اختبارات Node المدمجة لفهرس المنتجات.
- تتحقق الاختبارات من وجود المنتجات التسعة بالضبط.
- تتحقق من تفرد المعرفات والمسارات.
- تتحقق من وجود بيانات أساسية وحالة تنفيذ صريحة لكل منتج.
- تتحقق من بقاء MESSENGER وWHATSMYGRAM منتجين مستقلين.
- GitHub Actions ينفذ اختبارات السجل ثم TypeScript validation وبناء Vite.

## 4. ما لم يُختبر بعد

- لا توجد حالياً Playwright E2E في الهيكل الجديد.
- لا يوجد اختبار Auth حي ضد Production أو Staging.
- لا يوجد اختبار RLS متكامل.
- لم يُختبر إرسال بريد أو SMS حقيقي.
- لم تُختبر مكالمات WebRTC/LiveKit على جهازين.
- لم تُختبر ميزات اجتماعية أو رسائل بعد إعادة البناء.

## 5. مصفوفة قبول الرحلات

- التسجيل بالبريد وتأكيده.
- تسجيل الدخول واستعادة كلمة المرور.
- تسجيل الهاتف وOTP الحقيقي عند تفعيل المزود.
- استكمال الملف والتحقق من تفرد اسم المستخدم.
- إنشاء منشور مع وسيط وصلاحياته.
- تعليق ورد وتفاعل ومشاركة.
- قصص وريلز وخصوصية مالك المحتوى.
- طلب صداقة وقبول ورفض وحظر.
- Messenger: فردي وجماعي ووسائط وصوت وقراءة الرسالة.
- WHATSMYGRAM: حساب هاتف ومحادثة مستقلة ومجموعة ووسائط.
- Meeting: إنشاء وانضمام ومضيف ومشارك ومكالمة فعلية.
- AI: جلسة وقيود الاستهلاك وسجل المحادثة.
- تبديل اللغة والاتجاه.
- المحفظة: لا تبدأ الاختبارات المالية قبل اكتمال النظام؛ ثم تُختبر الذرية والتكرار والدفتر.
- اختبار اثنين أو أكثر من الحسابات في جلسات متصفح مستقلة.

## 6. بيئات الاختبار

- Staging هي الهدف الأول لاختبارات التكامل الحساسة.
- لا تستخدم بيانات مستخدمين حقيقيين في الاختبارات الاصطناعية.
- تحفظ أسرار المزود في إعدادات البيئة لا في ملفات المستودع.
- بعد النشر يُعاد اختبار Smoke من رابط الإنتاج من دون كتابة بيانات تجريبية في حسابات حقيقية.

## 7. تصنيف النتيجة

- IMPLEMENTED
- TESTED
- VERIFIED
- PARTIAL
- BLOCKED
- NOT IMPLEMENTED

تظهر نتيجة كل فحص مع وقت التنفيذ والفرع والـCommit SHA واسم البيئة.
