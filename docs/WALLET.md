## 2. أسماء الجداول المستهدفة

الأسماء الواردة في أمر التنفيذ وتحتاج مراجعة مخطط نهائي:
- `wallets`
- `wallet_transactions`
- `wallet_ledger`
- `wallet_private`
- `migration_import_jobs`

لا تُنشأ هذه الجداول قبل تصميم العلاقات والمفاتيح والقيود وRLS والمحاسبة واختبارات التزامن.

الكميات الرقمية المذكورة:

**التوزيع بين العملات الثلاث غير مثبت هنا**؛ يجب الرجوع إلى جدول التوزيع المالي المرجعي قبل تخزين أي كمية أو إنشاء عقد أو Migration.

## 4. المكافآت والخزينة

متطلبات مبدئية بانتظار مواصفات تنفيذية كاملة:
- مكافأة 10,000 للمستخدمين المؤهلين ضمن أول 5 ملايين مستخدم.
- الأهلية تُحتسب مرة واحدة لكل حساب وبآلية تمنع التكرار.
- النسبة المذكورة: 10% حرق و90% خزينة.

ما لم يُحسم: العملة، وحدة الحساب، لحظة احتساب النسبة، أساسها (إصدار أم تحويل أم رسوم)، قيود الخزينة، سياسة الاستحقاق، المعالجة المحاسبية والقانونية والضريبية.

## 5. ضوابط تنفيذ إلزامية

- دفتر قيود غير قابل للتعديل بعد الترحيل.
- كل عملية لها معرف ثابت وIdempotency Key.
- معاملات ذرية وموازنة Debit/Credit.
- لا تعديل مباشر للرصيد لتجاوز دفتر القيود.
- منع الرصيد السالب إلا وفق سياسة موثقة.
- صلاحيات إدارة منفصلة ومراجعة مزدوجة للعمليات الحساسة.
- اختبارات تزامن وتكرار وفشل وانقطاع وإعادة محاولة.
- حفظ أدلة التدقيق والتوقيعات والمرجع الخارجي لاحتياطي المؤسس.

## 6. بوابة ما قبل البناء المالي

لا تنفذ معاملات أو مكافآت حقيقية حتى يتم:
1. توثيق جدول التوزيع النهائي للعملات.
2. اعتماد تعريف الحرق والخزينة والنسب.
3. اعتماد سياسة المنحة وشروط أهلية أول 5 ملايين.
4. مراجعة قانونية ومحاسبية.
5. تصميم Migration آمنة واختبارها على Staging.
6. اختبار نزاهة ledger مستقلاً عن واجهة المستخدم.
