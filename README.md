## قواعد لا يجوز تجاوزها

1. لا تُحذف بيانات Auth أو الملفات الشخصية أو المنشورات أو الرسائل.
2. لا يُعطّل RLS لتجاوز خطأ.
3. لا تُنفّذ Migration مدمرة على Production.
4. لا يُعلن اكتمال وظيفة بسبب وجود واجهة أو زر.
5. لا يُنشر إصدار إنتاجي قبل نجاح اختبارات Staging والاختبارات المتأثرة.
6. لا تُخزّن مفاتيح الخدمة السرية في الواجهة أو GitHub.
7. أي وظيفة مالية تحتاج مواصفات محاسبية وقانونية واختبارات نزاهة مستقلة.

## مصدر الحقيقة

قاعدة الهوية هي Supabase Auth، والملف العام المعتمد هو `public.profiles` بعد استكمال تدقيق ترحيل الجدول القديم `public.users`. لا تُنشأ هوية ثانية أو جداول مكررة لمجرد بدء الواجهة من الصفر.
